## 一、目标与非目标

### 1.1 问题陈述
nexus 价值函数 = **agent 行为质量**（记忆检索准不准、任务完成得好不好、Telegram 交互顺不顺），非 Python 性能。自我改进对象 = **prompt / skill / 检索策略**。

### 1.2 目标

| 层级 | 目标 | 可度量 |
|---|---|---|
| **G-1（首要）** | 不可作弊的 eval 基线：把"变好了"变成可机算标量 | eval 集 ≥8 用例 / 4 难度层；baseline 连跑 5 次方差 <5%（温度=0、冻结记忆） |
| **G-2** | hermes 侧黑盒评估器，NPC 不可读写 | 仓库内 grep 不到评估器/用例代码 |
| **G-3** | 首靶在 **held-out 集**（4 例）加权均分 **≥ +0.05（绝对）且零回归用例** | held-out 分数 delta（见 §3.3 量化定义） |
| **G-4** | 保护内核零被修改 | diff 审计 |
| **G-5** | 2027 常态（每月数十次）仍工作 | 常态容量推演通过 |

### 1.3 非目标
1. ❌ 不优化 Python 代码性能。
2. ❌ eval 集建好前不启动任何迭代循环。
3. ❌ 不让 agent 参与构建或读取评估器（F1–F6）。
4. ❌ 不做开放式 autosearch / NEVER STOP（F8 82.5% 未纠正自我觉察）。
5. ❌ 不用 MiroFish 做方向层（领域错配）。
6. ❌ 不依赖促销窗口做可持续性设计。

### 1.4 量化粒度定义（修复 P3）
- 每用例 score = 其全部**断言的 partial-credit 均值**（每条断言命中=1.0，部分命中按子项比例，完全未中=0）。
- 数据集 score = 各用例 score 的**算术均值** ∈ [0,1]。
- 因断言分级，单用例翻转不再等于 12.5% 整跳；**G-3 的 +0.05 绝对提升在数学上可分辨**。
- 回归用例 = held-out 中任一用例 score 相对 baseline 下降 >0.02（绝对值）；出现即判过拟合（熔断 1）。

## 三、架构设计

### 3.1 定位（v2 M1 落地，维持）
NPC = **受外部调度的高质量提案生成器**。本地化理由：① NPC 流水线无状态 ② 成本独立于促销窗 ③ 本地迭代零核时。

### 3.2 双容量模型
**窗口期（→2026-12-31）**：0 credits；1600 核时；0.07 核时/成功任务 → ≈2.3 万次/月（保守 1.1 万）。
**常态（2027 起，⚠️推算 ±1 数量级）**：500 credits≈¥25 → ¥0.16/MTok 观测 → ≈98 次/月（标"±1 量级"，A1 窗口期不适用、A2 待 2027 查）。

### 3.3 数据流与信任边界（v2 三层论证，维持 + P7 补鉴权）
```
[hermes 侧｜NPC 不可达｜PSK 网关后置]
  eval 集(含 held-out) · 评估器 · expected.json · 保护内核副本
  POST /eval {repo,base_ref,diff_patch,target} → {score,breakdown,kept}  ← 仅标量，不带用例
        │ 只回传标量
[本地有界迭代｜用户 PC + n-omn 免费池｜驱动器=本地 CodeBuddy 会话]
  改 → commit → 调 /eval → 中位数决策 keep/revert → 记 attempts(落 worktree 外)
        │ 批次结束
[CNB｜NPC 只搬运已验证 diff → 一个逻辑改动=一个 PR｜平台禁止 AI 合并]
  人工复审 → 合并（唯一状态转移点）
```
**/eval 鉴权（P7）**：复用 n-omn gate 模式（Bearer PSK → 后置），仅接受 hermes 内网或前置网关；NPC 即便拿到路径也无法伪造（无 PSK 且返回体不含用例）。

### 3.4 保护内核落地（v2 §4.4，维持）
派发通路 / 持久层 / 鉴权 / CI 提权面（`.cnb.yml` `.cnb/settings.yml`）/ 审批路径 / eval 与评估器 / 目标函数显式化 —— 七类对象强制手段 + 检测方式同 v2。跨仓开关保持关闭（D8）。

### 3.5 评估执行器（**v3 新增，P1**）
缺它则 Gate 0–2 全空转。定义：
- **输入**：一个 prompt/检索策略 diff（repo+base_ref+patch）。
- **执行**：在隔离 git worktree 起 hermes 副本（用同一 Neon/R2 连接，但**只读快照** memory 状态）→ 对 8 用例逐条回放（经 n-omn 免费池调模型）→ 抓取 trace JSON（memory_hits / dispatch / actions / turns / answer）。
- **产出**：trace → `score.py`（§5 评分）→ 标量。
- **成本**：0（n-omn 免费池）；单次全量 eval ≈ 8 用例 × 平均 3 轮 ≈ 24 次模型调用，baseline ×5 ≈ 120 次/批基线，迭代 N 批 × K 重跑。
- **代码**：`loop.py` 实现「取 diff→起 worktree→跑 harness→汇总分数→决策」；harness 与 score.py 由**人**写（非 NPC，违反非目标 3）。

### 3.6 真相源落盘（**v3 新增，P4**）
`attempts.jsonl` 写入 **worktree 外**：`~/.nexus-eval/attempts/<batch>.jsonl`，**每日 R2 快照**（nexus 现有通路）。`notes.md` 同目录。reset --hard 不再吞记录。

## 四、实施步骤（可执行）

### 阶段 0 —— 建 eval（前置，未完成不得启动后续）
| 项 | 内容 |
|---|---|
| 目标 | 把"变好了"变成可机算、难伪造标量 |
| 动作1 | `eval_cases/`（4 层 ×8 例）：易2/中3/难2/边界1；每例 `prompt.md` + `expected.json`（**断言分级**：每条 `weight` + `check`） |
| 动作2 | `expected.json`：`must_hit_memory`/`must_dispatch`/`must_refuse`/`banned_patterns` + 注解每条断言权重（和为 1） |
| 动作3 | **held-out 4 例**，全程不参与优化，仅终验（防过拟合） |
| 动作4 | `score.py` 复用 Langfuse 公式但**适配本场景**：`score = correctness*0.5 + completeness*0.3 + efficiency*0.2`；correctness=断言分级命中均值；completeness=应执行动作完成比例；efficiency=回合数/延迟惩罚（见 §5） |
| 动作5 | 保护内核硬编码：`banned_patterns` 命中 → correctness=0 |
| 产出 | eval_cases/ + heldout/ + score.py + replay harness 骨架 |
| **Gate 0** | ① score.py 一键出 [0,1]；② **冻结 memory 快照**下 baseline 跑 **n=5**（温度=0、固定 seed）方差<5%；③ held-out 4 例隔离；④ 违规输出归零自测通过；⑤ **评估器/用例由人写、repogrep 为空** |

### 阶段 0.5 —— 评估执行器（**v3 新增，P1**，Gate 0 后可并行）
实现 `loop.py` + harness：取 diff→隔离 worktree→回放→抓 trace→score。干跑 1 次验证端到端无报错。**Gate 0.5**：1 次全量 eval 在 <X 分钟内完成且分数可复现（n=2 差<2%）。

### 阶段 1 —— hermes 侧黑盒评估器（v2，维持 + P7）
`POST /eval` 接口 + 隔离评估环境 + PSK 鉴权；dry-run 高分/归零两类。**Gate 1**：grep 锚定 `eval_cases/|/expected\.json$|/score\.py$` 为空；违规 diff `kept:false` 不生成 PR。

### 阶段 2 —— 本地有界迭代（**v3 修正 P2/P4/P12**）
| 项 | 内容 |
|---|---|
| 驱动器 | **本地 CodeBuddy 会话（经 n-omn 免费池）**，非 CNB NPC |
| 动作1 | 首靶：hermes 路由 prompt 或 mem0 检索策略（一次一假设，不限一文件） |
| 动作2 | git worktree 迭代：`commit → 调 /eval → 取同 diff K=3 中位数 → 升则 keep 降/崩则 revert` |
| 动作3 | 停止：连续 5 次无改进即停 |
| 动作4 | attempts 记 `~/.nexus-eval/attempts/<batch>.jsonl`（**worktree 外**）+ 每日 R2 快照 |
| 动作5 | 批次末跑 held-out sanity（不参与决策） |
| **Gate 2** | ① ≥1 改动 eval 加权均分 ≥+0.03；② 停止/预算触发；③ 批次报告含已知未修问题 |

### 阶段 3 —— CNB PR + 人工合并（**v3 修正 P5**）
| 项 | 内容 |
|---|---|
| 动作1 | **NPC 只搬运已验证 diff**：读 stage2 产物（commit/补丁），不开新写；一个逻辑改动=一个 PR |
| 动作2 | 若因技术原因需 NPC 重写 → **PR 合入前强制重跑 eval**（Gate 2 等价） |
| 动作3 | 触发：`cnb build start-build ... --event api_trigger_npc`（main: 包裹、sandbox:false、role 在 settings.yml 定义） |
| 动作4 | 人工按"审初级工程师 PR"对照表复审 |
| 动作5 | 合并（平台禁止 AI 合并） |
| **Gate 3** | 每 PR 有人工签字；零 AI 合并；保护内核零命中；**合入后触发 §7.4 回滚预检** |

## 五、评分公式（适配本场景，修复 P3）

```python
# score.py 伪代码
per_case = mean( [assertion_weight_i * hit_fraction_i for each assertion] )   # 分级
dataset  = mean(per_case over cases)
score = 0.5*correctness + 0.3*completeness + 0.2*efficiency
# correctness = dataset（断言命中均值）
# completeness = 应执行动作(如 memory.search/dispatch)出现比例
# efficiency   = max(0, 1 - max(0, turns - max_turns)/max_turns)  # 或检索延迟归一
# banned_patterns 命中 → correctness = 0
```
**为什么分级**：二元断言使 8 用例仅 9 个离散值，5%/10% 阈值落在噪声下；分级后 G-3 的 +0.05 可分辨。

## 七、验收标准

### 7.1 阶段门禁
- **Gate 0**：score.py 出标量 ✅｜冻结快照 n=5 方差<5% ✅｜held-out 4 例隔离 ✅｜违规归零自测 ✅｜评估器由人写 ✅
- **Gate 0.5**：端到端干跑 1 次完成、n=2 差<2% ✅
- **Gate 1**：grep 锚定为空 ✅｜dry-run 两类正确 ✅｜违规不生成 PR ✅
- **Gate 2**：≥1 改动 +0.03 ✅｜停止/预算触发 ✅｜报告含未修项 ✅
- **Gate 3**：人工签字 ✅｜零 AI 合并 ✅｜保护内核零命中 ✅｜合入触发回滚预检 ✅

### 7.2 全局（G-1~G-5）
同 §1.2，G-3 口径按 §1.4（held-out 加权 +0.05 且零回归）。

### 7.3 熔断反验收
1. 🔴 held-out 降 → 过拟合，本批作废
2. 🔴 保护内核任一行 diff → 停+人工
3. 🔴 移除审批/确认步骤 → 拒
4. 🔴 删未测功能 → 拒
5. 🟠 单批核时 >20（≈285 次 NPC 调用预算）
6. 🟠 /eval 上下文现评估器路径 → 隔离失效

### 7.4 回滚 SOP（**v3 新增，P8**）
合并后若生产指标异动（Telegram 失败率↑、task 成功率↓、held-out 重跑降）：
1. detect：监控告警（§7.5）或人工
2. `git revert <merge>` + 重部署 hermes（HF 重新 deploy）
3. 重跑 held-out 确认恢复
4. 事故记 `~/.nexus-eval/incidents/<date>.md`（含 diff、影响、根因）
5. 复盘是否需补 eval 用例防复现
**预期效果**：合并后回归可救，不污染持久层。

### 7.5 监控指标（**v3 新增，P9**）
| 指标 | 来源 | 频率 |
|---|---|---|
| eval 加权均分趋势 | attempts.jsonl | 每批 |
| held-out 漂移 | 批次末 run | 每批 |
| 核时/月账 | `cnb charge get-volume` | 每月计费日 |
| merge / rollback 率 | incidents/ | 每月 |
| 单批 attempts / 停止原因 | attempts.jsonl | 每批 |
**看板**：`~/.nexus-eval/dashboard.md` 由 loop.py 自动追加；异常（held-out 降、rollback>0）标红。
