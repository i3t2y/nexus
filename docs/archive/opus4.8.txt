## **0. 一句话定义与设计原则**

**Nexus = 计算与存储分离的混合 Agent 系统**：用 Hugging Face Spaces 当低成本计算单元，Cloudflare R2 存大文件/产物，Supabase Postgres 存结构化状态与记忆。一个常驻的 `hermes` 主控（自建 Gradio + FastAPI，**非 Hermes 原生 CLI**）按 prompt 关键词把任务路由到三个下游 Space——`langgraph`（编排）、`claude-code`（强推理）、`codex`（快速编码）；Cloudflare Worker 做统一鉴权入口与保活探测。

```
用户请求 ──> [hermes /run] ──路由──> Worker网关 ──> 下游Space ──> R2 / Supabase
                                       (langgraph / claude-code / codex)
   Dashboard(UI) + FastAPI(同进程7860)            结果回写数据库
```

四条设计原则：① **计算与存储分离**（Space 重启/休眠不丢数据）② **唯一入口路由**（下游 Space 不直接对外，全经 Worker 鉴权）③ **凭证外置**（全走 Secrets/环境变量，不入库不入码）④ **模板先行**（代码即可部署，填凭证即运行）。

## **3. API 契约（端到端）**

所有调用：JSON POST，Header `Authorization: Bearer <NEXUS_API_KEY>` + `Content-Type: application/json`。

### **3.1 hermes 对外接口**

| 方法 | 路径 | body | return | 说明 |
|------|------|------|--------|------|
| GET | `/health` | — | `{status,space}` | 保活/唤醒 |
| POST | `/run` | `{prompt, force_space?}` | `{task_id, space, result}` | 主入口：路由→下游→回传 |
| GET | `/state/{thread_id}` | — | state | 查状态 |
| UI | `/` | — | Gradio Dashboard | 任务路由 + R2 文件管理 + 系统状态 |

路由规则（`main.py` `route()`）：含"规划/多步/工作流"→langgraph；"实现/重构/调试"→claude-code；"补全/快速/片段"→codex；默认 langgraph。`force_space` 可强制目标。

### **3.2 下游 Space 接口**

| Space | 端点 | body | 模型 env |
|-------|------|------|---------|
| langgraph | `POST /execute` | `{thread_id, prompt}` | LangGraph 状态机（真实接 LLM 自填） |
| claude-code | `POST /run` | `{thread_id, prompt}` | `ANTHROPIC_API_KEY` + `CLAUDE_MODEL` |
| codex | `POST /complete` | `{thread_id, prompt}` | `OPENAI_API_KEY` + `OPENAI_BASE_URL` + `CODEX_MODEL` |

全部下游 Space 也有 `GET /health` 与统一 `auth()`（配了 `NEXUS_API_KEY` 则校验，模板阶段未配放行）。

### **3.3 调用链**

```
用户 ─POST /run──> hermes
  hermes: 生成 thread_id, route() 决策 space
  hermes: log_task(...,"route→<space>","pending") + save_state(...,"dispatched")
  hermes ─call_space(space,path,payload)──> [Worker /route] ──> 下游 endpoint
  下游: log_task(...,"running") → 执行(写R2/调LLM) → log_task(...,"done")
  hermes: log_task(...,"done") + save_state(...,"done",result)
  return {task_id, space, result}
```

`call_space` 逻辑：有 `GATEWAY_URL` 先经 Worker `/route`；2xx 用，404 视为网关未配转回退，其它非 2xx `raise_for_status`；网关超时/连接错误静默转回退直调 `{SPACE}_URL`。两者都无则抛错。

### **4.4【核查修正】LangGraph 与 Supabase 连接串**

HANDBOOK 原文让 langgraph 用 **transaction pooler（端口 6543）**，但这与 `AsyncPostgresSaver` 依赖的 prepared statements 冲突，会报 `prepared statement "..." does not exist`。两个可行修正：

- **方案 A（推荐）**：用 6543 事务池但在驱动层禁用预处理语句缓存——asyncpg 设 `statement_cache_size=0`、`prepared_statement_cache_size=0`，SQLAlchemy 用 `NullPool`。
- **方案 B**：改用 **session pooler / 直连（端口 5432）**，保留完整会话特性与 prepared statements，代价是并发连接数较少（免费层足够）。

不建议照抄"直接用 6543"而不做驱动配置。[GitHub langgraph#2755](https://github.com/langchain-ai/langgraph/issues/2755) [Supabase 连接指南](https://www.weweb.io/blog/supabase-connection-string-guide-ports-pooling)

## **6. 增强机制**

| 机制 | 实现 | 文件 |

| Dashboard 文件管理 | Gradio Tab：R2 上传/读/编辑/保存/删除/刷新 | `spaces/hermes/app/main.py` |

**hermes `start.sh` 启动流程**：① `replay_packages.py replay` ② 若 `SUPABASE_URL` 非空 → 后台 `persist_to_r2.py` ③ 若 `KEEPALIVE_ENABLED=1` → 后台 `keepalive.py` ④ 主循环 `while true; uvicorn app.main:app :7860` 自愈。

**保活策略（三层）**：主用外部监测网站 ping 各 Space `/health`；辅用 Worker cron + `keepalive.py` 内部互探；**额外必须**用其中一条定时写 Supabase 表，规避 7 天暂停。

## **7. 端到端部署（接手即跑顺序）**

**前置账号确认**：HF **需 PRO/Team**（否则建不了 3 个 Docker 下游 Space）；Cloudflare R2 免费 10GB+100 万 Class A/月；Supabase 免费 500MB+2 项目（注意 7 天暂停）；GitHub 私有库。

**步骤 1 · Cloudflare R2**：建 5 个桶；Manage R2 API Tokens 生成密钥记录 `R2_ACCESS_KEY_ID/SECRET/ENDPOINT`；每桶设 Lifecycle 清 `tmp/`。

**步骤 2 · Supabase**：建项目记录 URL/anon/service_role；SQL Editor 跑 `00_schema.sql`（需向量再跑 `01_pgvector.sql`）；按 4.4 取连接串给 langgraph（6543+禁预处理，或 5432 直连）。

**步骤 2.5 · 同步共享库（关键易漏）**：
```bash
bash scripts/sync-spaces.sh   # libs/ → spaces/*/libs/
```
每次改根 `libs/` 后、push 前必跑。

**步骤 3 · 部署 hermes**：HF New Space(docker,私有,名 `hermes`)；Settings→Secrets 加 hermes 所需全部；push `spaces/hermes/`；验证 GET `/health` 200、POST `/run` 返 task_id、`task_logs` 有记录。

**步骤 4 · 部署下游**：依次 langgraph/claude-code/codex，New Space(docker,私有)，按表加 Secrets，push 对应目录，GET `/health` 200。

**步骤 5 · Worker 网关**：
```bash
cd workers/gateway && npm install
npx wrangler secret put NEXUS_API_KEY     # 与各 Space 同一把
# 编辑 wrangler.toml 的 SPACE_OWNER = <你的HF用户名>
npx wrangler deploy
```
记下输出 URL 填 hermes 的 `GATEWAY_URL` Secret。

**步骤 6 · 端到端**：
```bash
curl -X POST <hermes_url>/run -H "Authorization: Bearer $NEXUS_API_KEY" \
  -d '{"prompt":"测试:让 langgraph 做一个三步规划"}'
```
期望：返 task_id，`task_logs` 全链 done，R2/Supabase 有产物。

## **10. 运维 / 排障 / 回滚**

| 症状 | 排查 |
|------|------|
| Space 起不来 | HF logs；README frontmatter `sdk:docker`/`app_port:7860`；Dockerfile `PYTHONPATH=.../libs` |
| `R2_ENDPOINT 未设置` | Secrets 漏 R2_*，或 sync 没跑致 `from storage import` 失败 |
| `prepared statement does not exist` | **见 4.4**：6543 需禁预处理缓存，或改 5432 |
| 下游 502/down | 先 `GET /health`；休眠冷启动等数十秒；Worker 转发超时调 `AbortSignal.timeout` |
| Supabase 突然连不上 | 检查是否 7 天无活动被暂停，Dashboard 一键恢复 + 补保活 |
| 401 unauthorized | `NEXUS_API_KEY` 各组件不一致，或 header 非 `Bearer <key>` |
| hermes 崩溃不重启 | `start.sh` while 循环 5s 重启；查 `logs/persist.log`/`keepalive.log` |

**回滚**：Space 出错→Settings→Restart 或 `git push -f` 回上个 commit；表结构→先备份再跑增量 `02_*.sql`；数据恢复→查 `backup_snapshots` 按 `table_name+created_at` 找 `r2_key`，从 R2 拉快照重建。

## **11. 成本与合规现实（更新后）**

| 项 | 费用 | 核查后备注 |
|----|------|------|
| HF Space | **非 0**（需 PRO \$9/月起） | 免费号无法建 4 个 Docker Space，这是原方案最大偏差 |
| Cloudflare R2 | \$0（10GB+100万A+1000万B，零出口） | 双写频率过高会击穿 Class A |
| Supabase 免费 | \$0（500MB+2项目） | 7 天暂停必须靠保活规避 |
| Claude/Codex API | 按量计费 | 主要可变成本，靠缓存+Skill 复用压降 |

**合规提示**：docx 中"多账号薅免费额度""分散请求避免特征""随机延迟降低被检测风险"等策略，本质是规避平台风控，可能违反 HF/Supabase 服务条款并招致封号。稳健做法是单个 PRO 账号 + 外置存储正规化运营，而非多号规避。这一点原方案存在合规风险，接手者应自行评估。
