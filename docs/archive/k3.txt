## **第二部分：系统概述**

### **一句话定义**

Nexus（星枢）= 混合 Agent 系统：以 Hugging Face Spaces 为低成本计算单元，Cloudflare R2 存大文件，Supabase Postgres 存结构化状态。一个常驻 `hermes` 主控 Space 接收请求并按关键词路由到 `langgraph`（复杂编排）、`claude-code`（强推理）、`codex`（快速编码）三个下游 Space；Cloudflare Worker 做统一鉴权入口与辅助保活。

```mermaid
flowchart TD
    U[用户/调用方] -->|POST /run| H[hermes 主控 Space<br/>FastAPI + Gradio Dashboard 同端口7860]
    H -->|关键词路由| W[Cloudflare Worker 网关<br/>鉴权 + /route 转发 + cron 保活]
    W --> L[langgraph Space<br/>AsyncPostgresSaver Checkpoint]
    W --> C[claude-code Space<br/>Anthropic API 转发]
    W --> X[codex Space<br/>OpenAI 兼容 API 转发]
    H -.->|网关404/超时自动回退直调| L
    L & C & X -->|状态/日志/记忆| S[(Supabase Postgres<br/>+ pgvector)]
    L & H -->|Checkpoint blob/产物/备份| R[(Cloudflare R2<br/>5个桶)]
    M[外部监测网站] -.->|定期 ping /health 主保活| H & L & C & X
```

### **设计四原则**

1. **计算与存储分离**：Space 重启、休眠、重建均不丢数据（全部状态外置 R2/Supabase）。
2. **唯一入口路由**：下游 Space 不直接暴露给最终用户，一切经 hermes 与 Worker 网关。
3. **凭证外置**：所有密钥走平台 Secrets/环境变量，绝不入库、绝不入 git。
4. **薄编排厚外包**：LangGraph 只跑轻量状态机，重推理全部外包给 Anthropic/OpenAI 兼容 API，使 2 vCPU/16GB 的 CPU Basic 硬件足以承载。

## **第四部分：关键决策——账号与部署拓扑**

### **决策一：放弃"多免费账号"，采用单 PRO 账号**

旧方案依赖 4 个免费 HF 账号各跑一个 Docker Space。核查后该路线已不成立：免费账号根本无法创建 Docker Space，且 ZeroGPU 是按 GPU 秒配额的共享推理资源（约 60 秒/次函数调用），不适合常驻 HTTP 服务。因此新拓扑为：

**一个 HF PRO 账号（\$9/月）创建全部 4 个 Docker Space，全部跑 CPU Basic（无小时费）。** 这是当前规则下的最低成本可行解，总基础设施成本 \$9/月 + LLM API 按量费用。

### **决策二（可选优化）：合并部署**

若追求极简，可将 4 个组件合并为 1 个 Space：hermes 的 FastAPI 内部直接 import langgraph 图逻辑与两个 API 转发模块，进程内调用零网络跳转。2 vCPU/16GB 完全够用（重计算在外部 API）。代价是失去独立扩缩与故障隔离。建议：原型期用合并版快速验证，验证通过后拆分为 4 Space 标准拓扑。

### **决策三：通信协议放弃"全 MCP"，采用 HTTP REST 为主**

MCP 适合 hermes 内部工具扩展（`hermes mcp add`），但跨 Space 服务间调用用 HTTP REST + `Authorization: Bearer` 更简单、可观测、易重试。最终：外部通信 HTTP REST，hermes 本地工具生态可用 MCP。

## **第六部分：API 契约与调用链**

全部调用：JSON POST，Header 带 `Authorization: Bearer <NEXUS_API_KEY>`。

| 组件 | 端点 | Body | 说明 |
|------|------|------|------|
| hermes | `GET /health` | — | 保活/唤醒探针 |
| hermes | `POST /run` | `{prompt, force_space?}` | 主入口：路由→下游→回传 `{task_id, space, result}` |
| hermes | `GET /` | — | Gradio Dashboard（`gr.mount_gradio_app` 挂载到 FastAPI 同端口） |
| langgraph | `POST /execute` | `{thread_id, prompt}` | 状态机执行，写 Checkpoint |
| claude-code | `POST /run` | `{thread_id, prompt}` | env：`ANTHROPIC_API_KEY` + `CLAUDE_MODEL` |
| codex | `POST /complete` | `{thread_id, prompt}` | env：`OPENAI_API_KEY` + `OPENAI_BASE_URL` + `CODEX_MODEL` |
| Worker | `POST /route` | `{space, path, body}` | 鉴权后转发对应 Space，下游超时 60s |
| Worker | `GET /probe` | — | 探测全部下游 `/health` |

调用链：hermes 收到 `/run` → 生成 `thread_id` → `route()` 按关键词决策（规划/多步/工作流→langgraph；实现/重构/调试→claude；补全/片段/快速→codex；默认 langgraph）→ `log_task(pending)` + `save_state(dispatched)` → `call_space()` 优先走 Worker `/route`，遇 404/超时/连接错误自动回退到 `{SPACE}_URL` 直调（总超时 90s 覆盖冷启动）→ 下游执行并写库 → hermes 落 `done`。

带重试的调用示例（修正版，全部 Space 共用 `libs/shared/gateway.py`）：

```python
import httpx
from tenacity import retry, wait_exponential, stop_after_attempt

@retry(wait=wait_exponential(min=2, max=20), stop=stop_after_attempt(3))
async def call_space(space_url: str, path: str, payload: dict, api_key: str):
    async with httpx.AsyncClient(timeout=90.0) as client:  # 90s 覆盖冷启动
        resp = await client.post(
            f"{space_url}{path}",
            json=payload,
            headers={"Authorization": f"Bearer {api_key}"},
        )
        resp.raise_for_status()
        return resp.json()
```

## **第七部分：数据存储契约**

### **分层原则**

| 层 | 存什么 | 何时用 |
|----|--------|--------|
| R2（S3 兼容，boto3，`region_name='auto'`） | Checkpoint blob、产物、备份快照、大文件 | >1MB 或二进制 |
| Supabase Postgres | agent_states / task_logs / long_memory / 索引 + pgvector | 结构化、需查询 |
| HF Datasets | 兜底临时缓存 | 仅低频，防风控 |

### **R2 桶规划（部署前手动创建）**

`nexus-checkpoints`（LangGraph blob）、`nexus-artifacts`（Dashboard 文件管理）、`nexus-backups`（Supabase 快照）、`nexus-skills`、`nexus-vectors`。全部私有，公开读走预签名 URL；每桶配 Lifecycle Rule 定期清理 `tmp/` 前缀。

### **Supabase 建表 SQL（幂等，`sql/00_schema.sql`）**

```sql
CREATE TABLE IF NOT EXISTS agent_states (
  thread_id TEXT PRIMARY KEY,
  state JSONB NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS task_logs (
  id BIGSERIAL PRIMARY KEY,
  thread_id TEXT, space_name TEXT, action TEXT, status TEXT,
  details JSONB, created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS long_memory (
  key TEXT PRIMARY KEY, value JSONB NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS backup_snapshots (
  id BIGSERIAL PRIMARY KEY, table_name TEXT, r2_key TEXT,
  row_count INT, created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS space_health (
  id BIGSERIAL PRIMARY KEY, space TEXT, status TEXT,
  detail JSONB, created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_task_logs_thread ON task_logs(thread_id);
```

全部表开启 RLS，服务端用 `service_role` key 绕过。向量检索再跑 `01_pgvector.sql`（`CREATE EXTENSION IF NOT EXISTS vector;` + `memory_vectors` 表 + HNSW 索引），pgvector 免费版可用。

### **同步策略**

Supabase → R2 快照每 5 分钟一次（原子写：先写 `tmp/` 再 copy 覆盖），并登记 `backup_snapshots` 表。恢复时按 `table_name + created_at` 找 `r2_key` 拉回 JSON 重建。此频率远低于 R2 每月 100 万 Class A 限额（5 分钟一次 ≈ 每月 8.6 千次写）。

## **第九部分：端到端部署步骤**

**前置**：HF PRO 账号、Cloudflare 账号（开 R2）、Supabase 账号、GitHub 私有库。

1. **Cloudflare R2**：建 5 个桶 → Manage R2 API Tokens 生成密钥对 → 记录 endpoint（`https://<account-id>.r2.cloudflarestorage.com`）→ 每桶配 Lifecycle 清 `tmp/`。
2. **Supabase**：建项目 → 记录 URL / anon / service_role → SQL Editor 跑 `00_schema.sql`（可选 `01_pgvector.sql`）→ 取 **6543 端口** 的 transaction pooler 连接串。
3. **同步共享库**：`bash scripts/sync-spaces.sh`。
4. **部署 hermes Space**：New Space（Docker、私有、名 `hermes`）→ Secrets 按第八部分表格注入 → push `spaces/hermes/` → 验证 `GET /health` 200 与 Dashboard 可开。
5. **部署下游 3 个 Space**：同上流程，各 push 对应目录，各验证 `/health`。
6. **部署 Worker**：`cd workers/gateway && npm install && npx wrangler secret put NEXUS_API_KEY` → 改 `wrangler.toml` 的 `SPACE_OWNER` 与 `crons` → `npx wrangler deploy` → 把输出 URL 回填 hermes 的 `GATEWAY_URL`。
7. **端到端验收**：`curl -X POST <hermes_url>/run -H "Authorization: Bearer $NEXUS_API_KEY" -d '{"prompt":"让 langgraph 做一个三步规划"}'`，期望返回 `task_id`，且 `task_logs` 全链 `done`。
8. **保活**：外部监测网站对 4 个 `/health` 设 5\~10 分钟间隔 ping（主）；Worker cron + hermes `keepalive.py` 为辅（间隔随机化，避免固定周期特征）。

```bash
while true; do
  uvicorn app.main:app --host 0.0.0.0 --port 7860
  echo "app exited ($?), restart in 5s..."; sleep 5
done
```

### **修正版 Worker 保活（scheduled 事件，非 setInterval）**

```typescript
export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    const url = new URL(req.url);
    if (url.pathname === "/health") return Response.json({ status: "ok" });
    if (!authorized(req, env)) return new Response("unauthorized", { status: 401 });
    if (url.pathname === "/route") return routeToSpace(req, env);   // 60s AbortSignal 超时
    if (url.pathname === "/probe") return probeAllSpaces(env);
    return new Response("not found", { status: 404 });
  },
  async scheduled(_e: ScheduledEvent, env: Env, ctx: ExecutionContext) {
    ctx.waitUntil(probeAllSpaces(env));   // Cron Trigger 驱动，wrangler.toml 配 crons=["*/10 * * * *"]
  },
};
```

## **第十部分：测试、成本与风险**

### **验收标准**

功能：`/run` 全链 `done`、R2 上传/下载/编辑正常、`agent_states` 随任务更新、快照写入 `nexus-backups`。压力：Vegeta 模拟 50 并发 3 分钟，平均响应 < 2s、错误率 < 5%（含冷启动的毛刺属预期，重试机制兜底）。

### **成本（修正后真实账目）**

| 项目 | 费用 | 说明 |
|------|------|------|
| HF PRO | \$9/月 | 创建 4 个 Docker Space 的前提；CPU Basic 硬件本身免费 |
| Cloudflare（Workers + R2） | \$0 | 均在免费额度内，注意 10万请求/天上限 |
| Supabase | \$0 | 500MB 内免费；每周有写入即不会被 7 天暂停 |
| LLM API | 按量 | 唯一变动成本，靠路由分流（便宜模型处理轻任务）压缩 |

即：**固定成本 \$9/月 + API 按量**，替代旧文档"\$0/月"的不实承诺。

### **风险与规避**

- **超配额**：Workers 超限返回 Error 1027 → hermes 回退直调 Space 兜底；R2 操作数留 10 倍余量。
- **Supabase 暂停**：系统自身 cron 保证每周有写入；若被暂停，到 Supabase Dashboard 一键 Restore 即可。
- **单点**：Worker 挂了自动回退直调；hermes 挂了 start.sh 5 秒自愈 + 外部监测告警。
- **合规**：多账号薅羊毛路线已废弃，单 PRO 账号无风控隐患；保活间隔随机化。
- **数据安全**：全 HTTPS；预签名 URL 短时有效；敏感写操作在 hermes 路由层加审批开关。

## **第十二部分：附录——Hermes Agent 真实命令速查（核查版）**

旧聊天记录中的命令大半是错的。以下是官方文档证实存在的命令，在 Space 内或本地使用：

- 聊天：`hermes chat`（交互）、`hermes chat -q "..."`（单次）、`hermes -z "..."`（脚本化纯输出，适合 cron 与管道）
- 模型：`hermes model`（终端内配置 provider/密钥）；会话内 `/model` 只能切换已配置的模型
- 技能：`hermes skills browse / search / install <源/路径或URL> / list / update / publish / tap`；会话内由 agent 自建 skill，`hermes curator run` 后台修剪合并
- 定时任务：`hermes cron create "every 1h" "任务prompt" --skill <名>`，另有 `list/edit/pause/resume/remove/status`；无异常时用 `[SILENT]` 静默模式
- 消息网关：`hermes gateway setup` + `hermes gateway run`（Docker/WSL 用 run，start 是 systemd 服务）——接 Telegram/Discord/Slack/WhatsApp，**不提供 HTTP API、无 --port**
- 检查点：`hermes checkpoints status/prune`，会话内 `/rollback` 回滚文件
- 档案：`hermes backup` / `hermes import <zip>`；多实例 `hermes profile create work --clone`
- Web 控制台：`hermes dashboard --port 9119`（需先 `uv pip install -e ".[web]"`，这是本地管理台，非任务 API）
- 记忆与人格：`SOUL.md`、`MEMORY.md`、`USER.md`、`AGENTS.md` 自动注入，可用 `--ignore-rules` 跳过 [Hermes Cron 文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)
