## 三、逐项修改建议（理由 + 预期效果）

| 对应 | 修改 | 理由 | 预期效果 |
|---|---|---|---|
| P1 | v3 新增 **§4.6 评估执行器**：定义 replay harness（取 diff→隔离 worktree 起 hermes 副本→回放 8 用例→抓 trace JSON→score.py）；明确 harness 调用 n-omn 免费池 | 没有执行器，Gate 0–2 全空转 | eval 闭环可跑，成本可算（走 n-omn 0 成本） |
| P2 | v3 §5 阶段2 明定**驱动器=本地 CodeBuddy 会话（经 n-omn）**，非 CNB NPC；给出 `loop.py` 伪代码 | 不指定驱动则无法启动 | 责任人/机器/成本三者落地 |
| P3 | score 改为**逐断言分级（partial credit）**，总分=各用例加权均值；G-3 改为"held-out 加权均分 ≥ +0.05 且零回归用例"，held-out 扩至 4 例 | 二元粒度使 5%/10% 不可测 | 阈值恢复可分辨 |
| P4 | attempts.jsonl 落地 worktree 外：`~/.nexus-eval/attempts/<batch>.jsonl` 并每日 R2 快照 | reset --hard 会吞真相源 | 审计链不断 |
| P5 | 阶段3 NPC **只搬运**已验证 diff（读 stage2 产物），不再重写；若重写则 PR 合入前强制重跑 eval | 防 eval/上线不一致 | 评估有效性闭合 |
| P6 | Gate 0 加：温度=0、固定 seed、冻结 memory 快照；baseline 跑 n=5 取方差 | 非确定下方差无意义 | 可复现基线 |
| P7 | /eval 强制 PSK 鉴权 + 仅接受 hermes 内网/前置网关；返回体不带用例 | 防伪造高分 | 评估器不可被作弊 |
| P8 | v3 新增 **§7.4 回滚 SOP**：detect→git revert→重部署→重跑 held-out→记事故 | 用户要求 + 生产安全 | 合并后回归可救 |
| P9 | v3 新增 **§7.5 监控指标**：eval 分趋势、held-out 漂移、核时月账、merge/rollback 率 | 用户要求 | 持续可观测 |
| P10 | v3 新增 **§十 里程碑**：M0–M4 事件驱动 + 人时 | 用户要求 | 进度可追踪 |
| P11 | grep 模式改为 `eval_cases/|/expected\.json$|/score\.py$` 锚定 | 防误报 | 审计干净 |
| P12 | keep/revert 取同 diff K=3 中位数 | 降噪 | 决策稳 |
| P13–P15 | 标注推算 ±量级；G1 改 ~249k；F12 降 🔶 | 诚实 | 事实准确 |
